Kluczowe spostrzeżenia AI
Bariera dostępu to główny hamulec dla GitHub Copilot – 47% nie ma dostępu. Nie jest to kwestia motywacji.
Weryfikacja wyników AI jest praktykowana: większość analityków świadomie weryfikuje odpowiedzi AI przed użyciem (wolne odpowiedzi).
GAIA – wewnętrzny asystent AI (eRU) – pojawia się jako przykład systemowego wdrożenia AI w PZU.
Potencjał nierealizowany: analitycy widzą możliwości AI w analizie wpływu, generowaniu avro/schematów, diagramów automatycznych.

Kluczowe wnioski i rekomendacje

Synteza wyników ankiety dla 74 analityków IT PZU

🔴 Wyzwania i luki
1. Wiedza w głowach, nie w systemach. 39% wskazuje bezpośredni kontakt z ludźmi jako główne źródło wiedzy o wymaganiach. Ryzyko utraty wiedzy przy rotacji.
2. Dokumentacja architektury prawie nieobecna. Średni wynik 1.73/5 – najniższy ze wszystkich typów dokumentów. Krytyczna luka przy systemach o bardzo wysokiej złożoności.
3. Git marginalizowany. 54% nigdy nie używa Git. W środowisku z mikroserwisami i repozytoriami to poważna bariera współpracy z deweloperami.
4. Python/Skrypty – prawie zero. 73% nie pisze żadnych skryptów. Potencjał automatyzacji analiz jest praktycznie niewykorzystany.
5. Brak standardu dokumentacji. 54% chce standardu, ale go nie ma. Różnorodność podejść utrudnia onboarding i wymianę wiedzy między zespołami.
🟢 Mocne strony
1. Dojrzały zespół. 73% to seniorzy 5+ lat. Głęboka wiedza domenowa i doświadczenie projektowe.
2. AI już działa. 72% używa AI kilka razy w tygodniu lub codziennie – w core workflow (US, dokumentacja, analiza). Nie trzeba przekonywać do AI.
3. Jira i Confluence zakorzenione. Prawie wszyscy używają obu narzędzi z wysoką satysfakcją. Dobra baza do budowania standardów.
4. User Stories – mocna strona. Wymagania funkcjonalne mają najwyższy wynik (4.03/5). Core kompetencja analityczna na wysokim poziomie.
5. Świadomość problemów. Respondenci trafnie identyfikują luki (dokumentacja, standardy, narzędzia). Gotowość do zmiany jest.
💡 Rekomendacje priorytetowe
R1. Standard dokumentacji (krótkoterminowe)
Wprowadzić lekki standard dla Confluence: szablony dla US, dokumentacji architektury i API. Zacząć od 2-3 szablonów, nie rewolucji.
R2. Szkolenie Git dla analityków (krótkoterminowe)
Dedykowane szkolenie Git na poziomie „analityk + repozytorium" – commit, PR review, przeglądanie historii. Nie full DevOps, ale funkcjonalna płynność.
R3. Licencje GitHub Copilot (krótkoterminowe)
47% nie ma dostępu, ale ma motywację. ROI szybki – analitycy już wiedzą jak używać AI. Priorytetowe dla grup z EA i IDE.
R4. Dokumentacja architektury – quick wins (średnioterminowe)
Warsztaty z EA dla grup, które go nie używają. Szablony architektoniczne w Confluence. Cel: każdy system ma co najmniej 1 diagram kontekstowy.
R5. SQL i podstawy Pythona (średnioterminowe)
50% pisze SQL regularnie – warto podnieść ten skill do poziomu zaawansowanego. Python basic (pandas, skrypty) dla chętnych jako ścieżka opcjonalna.
R6. Program "Wiedza uchwycona" (długoterminowe)
Adresowanie ryzyka wiedzy w głowach: regularne sesje knowledge-transfer, obowiązkowa aktualizacja Confluence po każdym sprincie, pair-analiza seniorów z juniorami.
